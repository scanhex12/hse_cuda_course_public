# GPU database

В этой задаче мы реализуем самую простую базу данных на GPU. База данных будет делать довольно простые вещи: получать запрос в виде строки и исполнять его. Разрешённые операции — `+`, `-`, `*`, `/` над столбцами (без агрегаций). Нужно реализовать класс `Database`, который выполняет запросы к таблицам на GPU. В этой задаче будем считать, что пользователь хочет выполнять один запрос несколько раз, поэтому будем выполянть запрос через CUDA Graph: один раз описывается весь план работы — какие ядра запускать и в каком порядке (чтобы, например, следующее ядро не стартовало, пока не готовы нужные буферы). Потом этот план можно выполнять много раз подряд дешевле по времени на запуск, чем если каждый раз отдельно вызывать `cudaLaunchKernel` для каждого шага.

Ниже будет представлено рекомендуемое API для решения задачи, однако вы можете все переписать как вам удобно, если считаете нужным (файл cuh менять можно)

## Лексер и парсер

Строка запроса сначала разбивается на лексемы. Лексер (`Lexer`) читает исходный текст слева направо и возвращает подряд токены: идентификаторы, точку, операторы, скобки, конец ввода (см TokenType). Это стандартный первый этап: из символов получаем осмысленные токены.

Затем парсер по потоку токенов строит дерево разбора (AST). У нас два вида узлов: ссылка на столбец `table.column` (`ColumnRef`) и бинарное выражение с поддеревьями (`BinaryExpr` с символом операции и указателями на левое и правое подвыражение). Разбор делается рекурсивным спуском: сначала выражения сложения/вычитания, внутри них термы умножения/деления, внутри факторы (идентификатор с точкой или выражение в скобках).

## AST и список ComputeNode

Публичный метод `Database::Execute` создаёт лексер и парсер по строке запроса, получает корень AST и должен превратить дерево в линейную последовательность узлов `ComputeNode` в векторе `nodes_` (индекс в векторе — это «номер узла» в дальнейшем).

Рекомендуемая схема: рекурсивная функция вроде `BuildDag(AstNode*)`. Для `ColumnRef` добавляется узел с `OpType::Load`, в полях `table` и `column` — имена; индексы детей не используются. Для `BinaryExpr` сначала рекурсивно обрабатываются левое и правое поддеревья (получаете два индекса `lhs` и `rhs`), затем добавляется узел с операцией `Add` / `Sub` / `Mul` / `Div` и этими индексами. Возвращаемый из обхода индекс последнего добавленного узла — корень выражения; его передаёте в `DownloadResult`.

Инвариант для бинарного дерева: индексы детей меньше индекса родителя, поэтому при построении CUDA Graph можно идти по возрастанию индекса и подключать зависимости к уже описанным узлам.

## Публичный интерфейс `Database`

- `AddTable(table, columns, data)` сохраняет на хосте имена столбцов и столбцы целых чисел `data` как вектор столбцов одинаковой длины (число строк). Реализация кладёт данные в `schema_` и `hostData_`.

- `Execute(query)` парсит запрос, строит `nodes_`, загружает таблицы на GPU, строит граф, запускает его, скачивает столбец результата (вектор длины числа строк) и возвращает его.

- Деструктор освобождает всё, что выделили на GPU (и уничтожает граф), чтобы не было утечек при повторных тестах.
