# Tensor cores

В этой задаче мы с вами научимся пользоваться тензорными ядрами. В качестве решаемой задачи будет LU-разложение матрицы.

## LU разложение

LU-разложение матрицы `A` - это запись в виде произведения

```text
A = L · U
```

где:

- `L` - нижняя треугольная матрица, на главной диагонали стоят единицы;
- `U` - верхняя треугольная матрица (под главной диагональю нули).

Это то же самое, что метод Гаусса без перестановок строк: множители, которыми вы обнуляете столбец под ведущим элементом, записываются под диагональю в `L`, а верхняя ступенчатая часть после исключения - это `U`.

### Пример, матрица 3×3

Исходная матрица `A`:

```text
     | 1   2   3 |
A =  | 4   5   6 |
     | 7   8  10 |
```

Шаг 1 - первый столбец. Из 2-й строки вычитаем 4× первую, из 3-й - 7× первую: `m[2][1] = 4`, `m[3][1] = 7`.

```text
     | 1   2   3 |
     | 0  -3  -6 |
     | 0  -6 -11 |
```

Шаг 2 - второй столбец. Из 3-й строки вычитаем `(-6)/(-3) = 2` × вторую: `m[3][2] = 2`. Получается верхняя треугольная матрица `U`:

```text
     | 1   2   3 |
U =  | 0  -3  -6 |
     | 0   0   1 |
```

Множители `m[2][1]`, `m[3][1]`, `m[3][2]` ставим в `L` под диагональю (на диагонали единицы):

```text
     | 1   0   0 |
L =  | 4   1   0 |
     | 7   2   1 |
```

Проверка: `L · U = A`. Например, третья строка:  
`7·(1,2,3) + 2·(0,-3,-6) + 1·(0,0,1) = (7, 8, 10)`.

Решение системы: после разложения `Ax = b` решают двумя проходами: сначала `Ly = b` (прямая подстановка), затем `Ux = y` (обратная).

## Блочное LU

Нетрудно убедиться, что наивная реализация плохо ложится на GPU-модель вычислений. Поэтому сделаем типичный шаг для задач с матрицами на GPU - нарежем матрицу на тайлы и решим LU в блочном виде. Разберём случай, когда сетка тайлов всего 2×2 (четыре блока одинакового размера `B x B`; последний ряд/столбец при необходимости меньше).

Запишем `A` как матрицу из четырёх блоков:

```text
      ┌───────────┬───────────┐
  A = │   A_00    │   A_01    │
      ├───────────┼───────────┤
      │   A_10    │   A_11    │
      └───────────┴───────────┘
```

Ищем такие же по размеру блоки `L_ij`, `U_ij`, чтобы `A = L · U`, при этом `L` - блочно нижняя с единичной скалярной диагональю внутри диагональных блоков, `U` - блочно верхняя, под главной блочной диагональю нули:

```text
      ┌───────────┬───────────┐         ┌───────────┬───────────┐
  L = │   L_00    │     0     │     U = │   U_00    │   U_01    │
      ├───────────┼───────────┤         ├───────────┼───────────┤
      │   L_10    │   L_11    │         │     0     │   U_11    │
      └───────────┴───────────┘         └───────────┴───────────┘
```

Шаг 1. Разложить левый верхний тайл - обычное LU размера `B x B`:

```text
A_00 = L_00 · U_00
```

Шаг 2. Досчитать верхнюю полосу `U` и левый столбец `L` из уже известных `L_00`, `U_00`. Это треугольные системы с несколькими правыми частями (по столбцам или по строкам внутри блока):

```text
L_00 · U_01 = A_01   ->  находим U_01
L_10 · U_00 = A_10   ->  находим L_10
```

Шаг 3. Обновить правый нижний тайл: вычесть вклад уже зафиксированных блоков (одно матричное умножение и вычитание):

```text
A'_11 = A_11 - L_10 · U_01
```

Шаг 4. Снова применить LU к обновлённому блоку `A'_11`:

```text
A'_11 = L_11 · U_11
```

После этого блоки `L_00`, `L_10`, `L_11` и `U_00`, `U_01`, `U_11` собирают полные `L` и `U` исходной матрицы. Если тайлов больше чем 2×2, после каждого обновления хвоста к следующему диагональному тайлу применяют тот же цикл: LU диагонали, треугольные решения для полосы справа и столбца снизу, затем ранг-обновление оставшегося угла через умножение блоков.

Итог: после разбиения на тайлы основная масса арифметики - обновление хвоста через умножение блоков, то есть GEMM; узкий LU на диагонали и треугольные решения по полосам - побочная часть.

## Интерфейс тензорных ядер

В CUDA доступ к тензорным ядрам в ядрах (device) обычно идёт через API WMMA (Warp Matrix Multiply Accumulate): заголовок `mma.h`, пространство имён `nvcuda` / `nvcuda::wmma`. Один вызов `mma_sync` выполняет весь варп совместно: каждый поток держит свою долю операндов и результата в регистрах в виде фрагментов (`wmma::fragment`), без явной адресации «мой элемент матрицы» внутри `mma`.

Общая схема одного умножения с накоплением:

1. Объявить три фрагмента: `matrix_a`, `matrix_b`, `accumulator` (тип и размеры задаются шаблонными параметрами).
2. `wmma::fill_fragment(acc, 0)` - обнулить накопитель.
3. Цикл по внутренней размерности `K` (если она больше, чем поддерживает одна инструкция `mma`):  
   `load_matrix_sync` для `A` и `B` из глобальной памяти во фрагменты (с указателем на начало подматрицы и шагом по строке `lda`, у нас матрицы в памяти row-major, шаг равен `n`).  
   `mma_sync(acc, a_frag, b_frag, acc)` - накопить произведение.
4. `store_matrix_sync` - выгрузить накопитель во временный буфер в shared или в массив в памяти, затем при необходимости сложить/вычесть с уже лежащими в памяти данными (как в коде: прочитать тайл `A22`, вычесть результат GEMM, записать обратно).

Параметры шаблона фрагмента задают геометрию одной операции `mma`. На Turing (например T4) операнды обычно в половинной точности: одна инструкция `16×16×16` закрывает весь внутренний размер тайла 16. На Ampere+ можно вместо этого взять TF32 (`16×16×8`, два прохода на полный 16) - другой тип фрагментов и `wmma::precision::tf32`. В этом репозитории в `lu_decomposition.cu` используется FP16 WMMA с накоплением в `float`: блок `float` из памяти переводится в `__half` в shared, затем `load_matrix_sync` из `__half*` с шагом 16.

### Пример: один тайл `C += A * B`

Один варп считает кусок `16×16` результата. `row`, `col` - левый верхний угол этого тайла в `C`, `lda` - длина строки в памяти

```cuda
#include <cuda_fp16.h>
#include <mma.h>
using namespace nvcuda;

// ... myA, myB — указатели на свои 16×16 __half в shared (по потокам заполнены из float)
wmma::fragment<wmma::matrix_a, 16, 16, 16, __half, wmma::row_major> a_frag;
wmma::fragment<wmma::matrix_b, 16, 16, 16, __half, wmma::row_major> b_frag;
wmma::fragment<wmma::accumulator, 16, 16, 16, float> acc_frag;

wmma::fill_fragment(acc_frag, 0.0f);
wmma::load_matrix_sync(a_frag, myA, 16);
wmma::load_matrix_sync(b_frag, myB, 16);
wmma::mma_sync(acc_frag, a_frag, b_frag, acc_frag);
wmma::store_matrix_sync(C + row * lda + col, acc_frag, lda, wmma::mem_row_major);
```

Без тензорных ядер это то же самое, что для среза `i, j = 0..15` записать один тайл матричного умножения (row-major, внутренняя сумма по 16):

```text
C[(row + i) * lda + (col + j)]
    = sum_{t = 0}^{15}  A[(row + i) * lda + t] * B[t * lda + (col + j)]
```

или в виде вложенных циклов на CPU/обычном kernel:

```cpp
for (int i = 0; i < 16; ++i)
  for (int j = 0; j < 16; ++j) {
    float s = 0.f;
    for (int t = 0; t < 16; ++t)
      s += A[(row + i) * lda + t] * B[t * lda + (col + j)];
    C[(row + i) * lda + (col + j)] = s;
  }
```

Для FP16 `16×16×16` на Turing одна `mma_sync` уже соответствует полной сумме `t = 0..15`, как в листинге выше. Внешний цикл по внутренней размерности (иногда с шагом 8) нужен, если K больше, чем даёт одна инструкция, либо при TF32, где за один проход только 8 по K; математически это всё та же полная сумма по `t`.
