## Flash Attention

Реализуйте Flash Attention. Тензорные ядра и CUTLASS в этой задаче использовать не нужно.

### Формула

`output = softmax(Q @ K^T / sqrt(d)) @ V`

параметры:
- Q, V: `N × d` (row-major)
- K: `d × N` (transposed layout — строки K соответствуют признакам)
- O: `N × d` (output)

### Алгоритм: онлайн softmax и блочная декомпозиция

Наивная реализация требует материализацию матрицы `N×N` (`Q @ K^T`), что неэффективно по памяти. Flash Attention разбивает задачу на блоки:

1. Разбиваем по блокам строки Q (итого на выходе получаем N/Br тайлов размера `Br x d`)  
2. Разбиваем по блокам столбцы K (итого на выходе получаем N/Bc тайлов размера `Bc x d`)  
3. Для каждого блока: `S_ij = Q_i @ K_j^T / sqrt(d)`, затем онлайн softmax с накоплением в O_i

### Онлайн softmax

Для численной устойчивости и отсутствия глобальной `N×N` матрицы используется рекуррентная схема:

- `m_i` — текущий максимум по строкам (running max)
- `l_i` — текущая сумма exp (running sum)
- При добавлении нового блока `S_ij`:
  1. `m_new = max(m_prev, rowmax(S_ij / sqrt(d)))`
  2. `P_ij = exp(S_ij / sqrt(d) - m_new)`
  3. `l_new = exp(m_prev - m_new) * l_prev + rowsum(P_ij)`
  4. `O_i := exp(m_prev - m_new) * O_i + P_ij @ V_j`

В конце: `O_i /= l_i`.

### Параллелизм между варпами

В качестве референса возьмем авторское решение, но тут можно и самому поэкспериментировать и посмотреть что будет лучше работать.

#### Как потоки назначаются на тайлы:
- `warp_id = tid / 32` — варп отвечает за строки: варп 0 — строки 0–3, 64–67, …; варп 1 — строки 4–7, 68–71, …
- `lane_id = tid % 32` — поток внутри варпа отвечает за столбцы: lane 0 — столбцы 0–3, 128–131, …; lane 1 — столбцы 4–7, 132–135, …
